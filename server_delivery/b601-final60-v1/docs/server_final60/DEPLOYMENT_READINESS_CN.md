# B601 部署检查与证据范围

本交付主模型为用户final-60数据微调的π₀.₅。模型可在Linux服务器推理，也可在用户Windows的WSL2中推理；两条路线都由Windows本机采集图像/关节反馈、使用原B601适配器通过USB执行。这里记录已经验收的软件行为，以及现场仍需确认的条件。

## 服务器发布前门槛

最终发布须使用实际长跑完成标记（活动墙钟≥44,100秒）、完整10-episode/5,118动作行评估、选模记录和独立最终审计。参数/优化器读回、所有交付候选golden、最终WebSocket及低显存运行、文件/压缩包/客户端ZIP哈希均有独立记录。以`INDEPENDENT_FINAL_AUDIT.json`的真实结果为准；本说明不把尚未执行的最终门槛当成通过。

已完成的软件工具验收：

| 检查 | 服务器证据与边界 |
| --- | --- |
| 客户端图像等价处理 | 211个真实验证观察经MsgPack后，图像/掩码/状态/指令与原模型输入逐元素一致；图像7.37MB降至0.30MB |
| 实际网络协议 | 三次紧凑输入RPC与独立原图直接推理结果一致，实际客户端CLI通过；服务器环回，不是用户WAN或Windows结果 |
| 代理与超时 | 仅模型连接显式直连；超时废弃连接，无自动重试，第二次请求被本地拒绝；独立CPU延迟服务器验收通过 |
| 动作检查器 | `action_guard.py`的36个合成CPU案例通过，绑定源码/模板SHA；没有打开USB或加载机械臂 |
| 初始禁用状态 | 交付配置的限位、速度、观察时限、校准引用为null，现场确认均为false，不能启用动作批准 |

完整记录在`receipts/CLIENT_PREPROCESS_EQUIVALENCE.json`、`CLIENT_TRANSPORT_ACCEPTANCE.json`、`CLIENT_TRANSPORT_ISSUE_RESOLUTION.json`及`ACTION_GUARD_ACCEPTANCE.json`。合成测试不等于真实B601硬件验收。

## Windows本机动作检查接口

`client/action_guard.py`只检查、不发送USB，也不会让正在运动的机械臂物理停止。应接入本机原有停止/保持策略，物理急停必须独立可用。未完成原B601适配器与控制循环集成前，本项目不能声称真机bridge已经可用。

1. 从实际硬件/校准及原适配器取得七轴`absolute_adapter_input`限位、命令空间速度上限、观察有效时限和校准引用，填写配置；不能用数据集最小/最大值冒充硬件限位。现场确认字段只能在实际确认后填写，不能把全填true当作测试结果。
2. 启用时须提供本机适配器最近明确接受的初始命令和时间；不能假设零位、模型第一帧或原始电机反馈就是已发送的adapter命令。尤其夹爪state与action尺度不同。
3. 原始观察捕获时间使用Windows本机`time.monotonic()`，不可使用服务器时钟、墙钟，或在RPC返回后重打时间。模型刷新与USB控制发送分离；同一25步chunk可共享原始观察时间，每步仍重新检查是否过期。
4. `check_next`只产生单个不可变批准对象，不提交状态；`before_send`必须在单一发送线程实际下发前就近调用，复核时效、急停、限位和速率，返回不可变七轴值。不得在批准后排队等待或随意修改数值，方向/夹爪变换由原适配器承担。
5. 仅在本机适配器明确确认接受同一adapter命令后调用`commit_sent`。时间不能早于实际发送前检查。候选命令不会自动变成last_sent；重复批准、替换、未确认、USB失败/状态不明均锁定禁用，不能自动重试或自动重新启用。

速率约束采用距上次成功发送的实际时间与0.04秒的较小值，防止停顿后一次跳大步。它约束的是命令变化，不证明电机实际速度、扭矩或到位。60秒网络响应时限用于样例首次JIT，不是完整推理调用或机械臂控制的硬实时保证；实际观察时效须由现场控制预算确定。

可在Windows先运行纯软件检查，不会控制机械臂：

```powershell
.\.venv-client\Scripts\python.exe .\client\guard_self_test.py
.\.venv-client\Scripts\python.exe .\client\deployment_check.py
```

默认第二条返回`needs_local_setup`和退出码2，是预期的禁用状态。配置完整时只表示字段和声明完整，脚本始终报告`hardware_verified_by_this_script=false`。

## 必须在用户现场验证

以下项目无法由本服务器完成，交付时保持待现场验证：实际USB设备身份与通信异常行为、相机位置/颜色/时间同步、校准和关节方向/夹爪比例、关节及工作空间限制、原停止/保持策略和物理急停、碰撞/夹伤风险、电机扭矩/电流/到位反馈、Windows/WSL资源与真实网络时延、闭环抓放成功率。

检查器失败时只会停止批准后续命令；不能撤回已经发出的动作，也不提供碰撞/力反馈保证。模型离线MAE、文件自检和软件检查通过均不能替代上述现场验证。
